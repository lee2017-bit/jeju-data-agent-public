# 문제 정의 (작업 가설 v0.3, 2026-11-02)

> **v0.3 갱신(운영진 답변 2026-11-02):** 현재 방문자 대다수는 **기관·기업**이고, 목적은 **논문·현황자료 작성, 사업계획서 작성** 위주.
> 센터 데이터는 별도 사이트 UI에서 메뉴로 조회·내려받기(SQL 없음), CSV는 영문 컬럼명·UTF-8.
> → 대상은 '현재 주 이용층(기관·기업)'과 '센터가 넓히려는 층(코딩 모르는 도민·소상공인)'을 함께 본다.
>   목적 선택지: 사업계획서·창업 / 가게·회사 운영 / 현황자료·보고서 / 논문·연구.

> 근거 표시: [확정] 공식 문서·의안·보도자료·운영진 답변, [추정] 정황 기반, [미확인] 자료 없음.
> 상세 출처: `docs/research/2026-11-01_center-users-identity-plans.json`, `docs/research/2026-11-01_contest-intel.json`

## 한 문장
**코딩을 모르는 도민(1순위: 소상공인·예비창업자)이 센터 PC에서 일상어로 물으면, 센터 데이터로 분석해 사업계획·지역 현안 문서에 넣을 근거(차트·수치·쉬운 해설)와 반출 가능한 결과물을 만들어 주는 분석 도우미.**
센터 직원이 연 12건 정도 대신 해 주던 분석·컨설팅을, 방문자가 혼자 할 수 있게 만드는 것.

## 이 센터는 무엇인가
- [확정] 「제주특별자치도 빅데이터 활용에 관한 조례」 제14조에 근거한 도 센터. 도 예산(2026~2028 연 2.396억 원, 동결)으로 제주테크노파크가 위탁 운영. 제주시 첨단로 제주TP 3층.
- [확정] 도가 구입한 유료 데이터와 공개하기 어려운 데이터(카드, 외식업 POS, 유동인구, 기업, 버스 등 65종)를 **센터 안 PC에서만** 분석하게 하는 오프라인 분석실. 제주데이터허브는 개방 데이터 다운로드와 센터 이용 신청 창구, 도청 내부망 '제주 빅데이터 플랫폼'은 공무원용.
- [확정] 국가 법률상 데이터안심구역 지정은 확인되지 않음(조례상 기관).

## 누가 오는가
- [확정] 이용자 수: 2023년 965명, 2024년 1,154명, 2025년 1~8월 464명(감소세). 하루 평균 몇 명 수준의 한산한 분석실. (도의회 의안 2795)
- [확정] 직원 분석·컨설팅: 연 10~12건. 대상은 도내 중소기업·소상공인·예비창업자. 목적은 "경영전략 수립", "효과적인 사업과 마케팅 계획 지원". 내용은 유동인구 시각화(신규 매장 입지), 매출·SNS 트렌드, 농산물 정보 시각화.
- [추정] 2026년 4월 이전 실제 방문층은 데이터를 다룰 줄 아는 대학(원)생·연구자·기업 실무자 중심(연구계획서 요건, 제주TP 스스로 '전문가 중심 공간'이라 표현).
- [확정] 공무원은 주로 내부망 플랫폼 사용 → 센터 주 이용층 아님.
- [미확인] 유형별 비중, 2026년 프리존 전환 이후 이용자 구성.

## 센터는 어디로 가려 하나
- [확정] 예산·공간 확장 계획은 확인되지 않음. 예산 감액으로 교육·경진대회가 거의 끊겼다고 도가 직접 기록.
- [확정] 확장 방향은 **대상과 방식**: 2026.4 '데이터 프리존'으로 전환해 "도민 누구나" 간소 절차로 이용, 2026.10 이번 챌린지 — 우수작을 분석실에 **상시 탑재**. 목적은 "파이썬 등 프로그래밍 언어에 익숙하지 않은 도민도 지역 현안 해결이나 사업 운영에 필요한 데이터를 손쉽게 분석"(제주TP 보도자료).
- [추정] 즉 Agent는 ① 직원 분석·컨설팅의 셀프서비스화, ② 끊긴 교육을 대신하는 자습 도구, ③ 소상공인 사업 운영 지원 역할을 기대받는다.

## 이해관계자
| 누구 | 목적 | 막히는 지점 | Agent에 필요한 것 |
|---|---|---|---|
| 방문 이용자: 코딩 모르는 도민. 1순위 소상공인·예비창업자, 2순위 학생·주민 | 사업계획·마케팅·지역 현안 문서에 넣을 근거 | 65종 중 뭘 쓸지 모름, 추출 방식(SQL 가능성) [추정], 분석 코드 못 짬, 해석 어려움 | 질문 → 데이터 선택·추출 조건·분석 → 쉬운 해설 |
| 기존 숙련 이용자: 학생·연구자·실무자 [추정] | 연구·과제 | 반복 작업, 반출 규정 | 생성된 코드·조건 보기·수정(고급 모드) |
| 센터 운영팀(제주TP) | 이용 확대, 적은 인력·예산으로 운영 | 1:1 지원 한계, 운영비, 규정 위반 위험 | 쉬운 설치·운영, API 비용 통제, 규정 자동 준수 |
| 반출 심사자(센터 내부) | 규정 맞는 결과만 반출 | 출처·사유 누락, 10 미만 수치 → 반려, 심사 최대 5일 | 규정 통과 결과물 + 신청서 초안 |

## Agent가 할 일 (5단계)
1. 질문 이해 → 어떤 센터 데이터를 어떤 조건으로 꺼낼지 추천
2. 센터 시스템에서의 추출 안내(필요 시 SQL 작성) [추정, 확인 필요]
3. 넣은 CSV를 로컬에서 분석 — 외부 LLM에는 스키마·질문·응용집계만
4. 차트·한 장 요약·근거(데이터명·기간)·한계 — 사업계획서·보고서에 붙일 수 있는 형태
5. 반출 패키지: 10 미만 처리, PNG·보고서 변환, 반출 신청서 초안(출처·활용 사유)

## 정의에서 주의할 점
- 문서를 읽어 분석하는 도구가 아니다. **센터 데이터를 분석해 문서에 넣을 근거를 만드는 도구**다.
- 대상은 "PC는 쓰지만 코딩·통계는 모르는" 사람(공식 표현: 'IT 비전문가', '프로그래밍에 익숙하지 않은'). 온라인으로 이용 신청하고 센터에 오는 사람이다.
- 공식 목적은 "지역 현안 해결이나 사업 운영" — 사업계획서만으로 좁히지 않는다. 시연 시나리오: ① 사업계획·입지 근거 ② 지역 현안 근거 ③ 학습용 단계 설명.
