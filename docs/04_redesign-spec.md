## 2. 설계 원칙(모든 화면 공통)
1. 한 화면에는 할 일 1개와 파란 주 버튼 1개만 둔다. 조건이 안 되면 버튼을 끄고 바로 위에 이유를 한 줄 적는다.
2. 결론을 먼저 보여 준다. 순서는 답 → 할 일 → 믿어도 되는 이유 → 근거 → 가져가기다.
3. 판정은 공개 규칙표(코드)로만 한다. AI는 질문 해석과 (선택) 문장 다듬기에만 쓴다. 같은 데이터면 늘 같은 결론이 나온다.
4. 영문 컬럼명, 필터식('bjd=…'), 표 번호를 제목에 쓰지 않는다. 표 번호는 회색 작은 글씨로만 쓴다.
5. 숫자는 항상 기준과 함께 쓴다: '제주 평균', '고르게 팔리면', '평소=100'.
6. 경고와 보조 정보는 한 곳(띠 1줄이나 접힘)에 모은다. st.info/warning/success 상자를 남발하지 않는다.

## 3. 화면 흐름
### 3.1 페이지와 모드
- `st.navigation([visitor_page, admin_pg], position="hidden")` [완료]. 방문자 페이지는 `/`, 운영자 페이지는 `/admin`(st.Page visibility="hidden")이다. 방문자 화면에는 운영자 링크·버튼·모델명·비용을 두지 않는다(test_app으로 고정).
- 실행 모드 `settings.app_mode`
  - `체험`: 저장소와 공개 데모의 기본값이다. ①에 '예시 결과 바로 보기'를 두고, ②에서는 체험 버튼을 주 버튼으로 맨 위에 둔다.
  - `센터`: install.ps1이 센터에 설치할 때 기록한다. 체험 버튼은 ② 아래쪽 접힘 '센터 데이터 없이 연습해 보기' 안에 둔다.
- 공개 데모: 환경변수 `JEJU_AGENT_DEMO=1`이면 /admin에는 안내문만 나온다(§12) [진행].

### 3.2 공통 틀
- 머리글: 왼쪽에 앱 이름(17px 800 파랑)과 소개 1줄('질문 한 줄이면 제주빅데이터센터 데이터로 답과 사업계획서·보고서용 근거 파일까지.'), 오른쪽에 '처음부터'(tertiary, :material/restart_alt:)를 둔다. '처음부터'는 질문·계획·결과·묶음·지원사업만 지우고 받은 데이터(loaded)는 남긴다 [완료].
- 진행 표시: 4칸 버튼 `1. 질문 / 2. 데이터 준비 / 3. 결과 / 4. 가져가기`, key=`step_{i}` [완료].
  - 현재 칸은 primary다.
  - 지난 칸은 '✓ n. 이름'으로 표시하고, 누르면 그 단계로 간다(auto_ok=False).
  - 아직 갈 수 없는 칸은 disabled다.
  - 갈 수 있는 조건: 2는 plan이 있을 때, 3은 plan과 result가 있을 때, 4는 result가 있을 때.
- 하단 고정 행동 막대 [할 일]
  - 구조: `with st.container(key="navbar", horizontal=True, horizontal_alignment="distribute")`. 왼쪽에 '← 이전'(tertiary, :material/arrow_back:), 오른쪽에 주 버튼 1개(primary, :material/arrow_forward:).
  - 주 버튼이 꺼져 있으면 바로 위에 `<div class='navwhy'>이유</div>`를 쓴다.
  - CSS로 sticky 처리한다(§8.3). 단계 함수마다 맨 끝에서 한 번만 그린다.
- 화면 맨 아래: '퇴실 전 내 작업 지우기'(tertiary, :material/delete:) → st.dialog로 확인 → `outputs/{sid}` 폴더를 지우고, admin*로 시작하는 키를 뺀 세션을 모두 지운 뒤 ①로 간다 [완료].

| ① 질문 | 없음 | '이 질문으로 시작 →'(동네·시·업종 중 1개 이상, 또는 순위 질문). 필요한 표가 이미 다 있으면 '바로 결과 보기 →'(②를 건너뜀) | '동네나 업종을 하나 이상 알려 주세요. 위 [고치기]를 눌러 고를 수 있어요.' |

## 6. 문장 틀
### 6.1 표기 규칙
- 숫자 자리
  - 결론 문장·숫자 타일·비유('100원 중 n원')는 정수로 쓴다.
  - 카드 문장·차트·보고서 문장은 소수 1자리로 쓴다.
  - 배율은 소수 1자리로 쓴다('1.6배'. HEAD의 '1.31배' 같은 2자리는 금지).
  - 지수는 정수로 쓴다.
  - 화면에 쓰는 반올림 값도 facts['applied']에 넣어서 '숫자는 분석 결과에서만 나온다' 테스트를 통과시킨다.
- 화면 단어 바꾸기
  - '%p' → '%포인트', '지수' → '평소 달=100', '법정동' → '동네'.
  - 업종 코드명은 쉬운 이름으로 쓴다(카페, 한식당).
  - '응용집계'는 직원용 접힘 안에서만 쓴다.
  - 보고서·사업계획서 문장에서는 '%p'와 '지수(평소=100)'를 써도 된다.
- 달 표기
  - 제목과 문장에서는 '8월'처럼 쓴다.
  - 12개월 창에 같은 달이 두 번 나올 때만 '2026년 2월'로 쓴다.
  - '26년 2월'처럼 두 자리 연도는 차트 x축에서만 쓴다. [할 일: 지금 계절 카드 제목이 '…가장 한산한 26년 2월의 1.6배']
- 기준 함께 쓰기: 비교하는 숫자에는 같은 문장 안에 기준을 붙인다('제주 카페 평균 49%', '고르게 팔리면 14.3%', '평소=100').
- 조사: korean.josa로 붙이고, 괄호가 있으면 괄호 앞 명사를 기준으로 한다(예: '제주 전체 한식당(47.0%)과'). [할 일: 지금은 '(47.0%)와'로 틀림]
- 표현 수위
  - 데이터 사실은 '~입니다', 해석은 '~로 보입니다', 권고는 '~해 보세요/검토해 보세요'로 쓴다.
  - 문장 하나에 숫자는 2개까지 쓴다.
- 금지어(테스트로 막는다)
  - 단정·과장: 반드시, 무조건, 확실히, 성공, 실패, 유망, 추천 입지, 안전, 열어도 됩니다, 열지 마세요, 창업하세요, 경쟁이 치열, 경쟁이 적.
  - 화면 문자열에 나오면 안 되는 것: bjd, biz_nm, use_amt, tour_type, dtYearMonth, ageGroup, 필터식의 '='.

### 6.2 종합 결론 문장(답 카드 b) [할 일]
변수: focus = plan.focus_label(예: '애월읍 카페'), 축 등급 = by[key].grade.

조립 규칙
- 축 순서: 사용자가 물은 관점(slots.views의 첫째)을 맨 앞에 두고, 그다음 손님 → 계절 → 요일·시간 순이다. 쓸 수 있는 축을 최대 3개 고른다.
- 어미: 1번째 축은 '-고', 2번째 축은 '-며', 마지막 축은 관형형 + ' 장사입니다.'
- 3축 틀: '{focus}{은/는} {축1.고}, {축2.며}, {축3.관} 장사입니다.'
- 2축 틀: '{focus}{은/는} {축1.고} {축2.관} 장사입니다.'
- 1축 틀: '{focus}{은/는} {축1.관} 장사입니다.'

| 축·등급 | 고 | 며 | 관형 |
|---|---|---|---|
| 뚜렷한 관광객 장사 | 관광객이 대부분이고 | 관광객이 대부분이며 | 관광객이 대부분인 |
| 관광객 장사 | 관광객이 더 많고 | 관광객이 더 많으며 | 관광객이 더 많은 |
| 관광객·도민 반반 | 관광객과 도민이 반반이고 | 관광객과 도민이 반반이며 | 관광객과 도민이 반반인 |
| 도민 단골 장사 | 도민이 더 많고 | 도민이 더 많으며 | 도민이 더 많은 |
| 뚜렷한 도민 단골 장사 | 도민이 대부분이고 | 도민이 대부분이며 | 도민이 대부분인 |
| 계절 영향 큼 | 계절을 많이 타고 | 계절을 많이 타며 | 계절을 많이 타는 |
| 계절 영향 있음 | 계절을 조금 타고 | 계절을 조금 타며 | 계절을 조금 타는 |
| 사계절 고른 편 | 사계절 고르고 | 사계절 고르며 | 사계절 고른 |
| 요일·시간(X) | {X}에 몰리고 | {X}에 몰리며 | {X}에 몰리는 |

- X 만들기: 요일이 주말형이면 '주말', 평일형이면 '평일'을 넣는다. 시간대가 집중형이면 1시간당 1위 시간대 이름을 넣는다. 두 말을 '·'로 잇는다(예: '주말·점심'). 둘 다 없으면 이 축은 뺀다.
- 경계 근접이면 손님 축을 '관광객이 더 많은 편이고/편이며/편인'으로 쓴다.
- 예(HEAD 체험 수치, T=61.2, R=1.6, 주말형, 점심 집중형): '[체험] 애월읍 카페는 관광객이 더 많고, 계절을 조금 타며, 주말·점심에 몰리는 장사입니다.'
- 예(요일·시간대를 물은 노형동 한식당, T=45.7, R=1.31): '[체험] 노형동 한식당은 주말·점심에 몰리고, 관광객과 도민이 반반이며, 사계절 고른 장사입니다.'
- 예(사용자가 받은 문서의 수치, T=56.0, R=2.24): '애월읍 카페는 관광객이 더 많고, 계절을 많이 타며, 주말·점심에 몰리는 장사입니다.'
- 지역 없이 순위를 물은 경우: '제주에서 {biz} 매출이 가장 큰 동네는 {top1}({s1}%)입니다.' [완료]
- 공개 데이터만 있으면 focus는 공개 카드의 대상(예: '제주시 읍면 지역 식음료')으로 쓴다 [완료].
- 가상 데이터면 문장 앞에 '[체험] '을 붙인다. 문장은 70자 안팎, 쉼표는 2개까지다.
- 중립 목적(현황자료·논문): '{focus} 매출의 {T}%는 관광객 결제다({기간}). 제주 {biz} 평균({B}%)보다 {|d|}%p {높/낮}다.' 등급 단어와 할 일은 쓰지 않는다.

- [할 일] 보조 1줄 '숫자가 다른 이유': '범위(시 읍면 식음료 vs 동네 카페), 기간(2016~2018 vs 최근 12개월), 관광객 정의(내국인만 vs 개별+단체)가 달라서 두 숫자를 서로 빼거나 비교하면 안 됩니다.'
- 보조 문장(접힘)
  - '같은 자료에서 관광객 매출은 최고 달이 최저 달의 {t}배, 도민 매출은 {l}배로, 관광객 비중이 높을수록 계절을 더 탑니다.'

- [진행] 보고서에 '다음 방문 때 이어서 하려면' 문단을 넣는다.
- (P2) 반출 묶음 zip에 '이어하기.csv'를 넣는다.
  - 내용: 질문·목적·동네·업종·지원사업 프로필·표 번호·기간. 데이터 값은 넣지 않는다.
  - 다음 방문 때 ① 화면의 접힌 업로더에 넣으면 질문과 프로필이 복원된다.
  - 센터 PC에서 바로 내려받는 버튼은 두지 않는다(반출 절차를 우회하는 것처럼 보이기 때문).

## 12. 운영자 모드와 PIN 흐름
```
/admin 접속
 ├ JEJU_AGENT_DEMO=1 → '공개 데모에서는 운영자 설정을 열 수 없습니다. 센터 설치본에서 PIN으로 엽니다.' (끝)
 ├ PIN 없음 → '설치 폴더의 set_pin.bat으로 PIN을 정한 뒤 다시 여세요.' (앱 화면에서 처음 PIN을 정하는 경로는 없음) (끝)
 └ PIN 있음 → 잠김 상태인가?
      ├ 예 → '{n}분 뒤 다시 시도하세요' (폼 비활성)
      └ 아니오 → PIN 폼(숫자 6~12자리, type=password)
            ├ 틀림 → 틀린 횟수 +1을 local_settings.json에 기록
            │        5번째: 5분 잠금 → 다시 5번 틀리면 15분 → 그다음 60분(LOCK_STEPS, lock_level)
            └ 맞음 → 틀린 횟수·잠금 초기화, session_state['admin_at']=now → 운영자 화면
운영자 화면: 상호작용마다 admin_at 갱신, 15분 동안 아무것도 하지 않으면 잠김, [잠그기] 버튼,
             방문자 화면(visitor())이 그려지면 admin_at 삭제
```
- 저장: PIN 원문은 저장하지 않는다. PBKDF2-SHA256(무작위 salt 16바이트, 20만 회) 해시·salt·틀린 횟수·잠금 해제 시각·잠금 단계만 config/local_settings.json(gitignore)에 둔다 [진행].
- set_pin.bat(`python -m jeju_agent.admin set-pin`): PIN이 이미 있으면 현재 PIN을 먼저 묻는다(맞지 않으면 PermissionError) [진행]. 처음 설정은 install.ps1 5단계에서 하고, 이때 app_mode=센터를 기록한다 [모드 기록은 할 일].
- reset_operator.bat(`... admin reset`): PIN 해시와 저장된 키(AI·데이터허브·공공데이터포털)를 모두 지우고 usage_log.jsonl에 '운영자 초기화'를 남긴다. 방문자가 실행해도 키는 얻지 못하고 AI만 꺼지므로 센터가 바로 알아챈다 [진행].
- 운영자 화면 구성
  - 실행 모드(체험/센터)
  - 데이터 폴더(사전 적재, 내려받기 감시)
  - 표별 바로가기
  - AI·외부 API: 모델, API 주소, 월 한도, '방문자 화면에서 AI 도움 쓰기', 키 3종(끝 4자리만 표시)
  - 방문 예약 준비
  - 공고 새로 받기(+자격 카드 갱신, P1)
  - 공개 데이터 새로 받기
  - AI 사용 금액(이번 달 / 한도, 최근 20건)
- 키 보호(매뉴얼에 정직하게 적는다)
  - PIN은 호기심과 실수를 막는 장치다. 같은 Windows 계정이면 설정 파일 자체는 열 수 있다.
  - 센터 비용을 지키는 실제 장치는 세 가지다: ① 공급자 쪽 프로젝트 전용 키와 월 예산 하드캡 ② 앱의 월 한도($10, 넘으면 규칙 모드로 동작) ③ 분기마다 키 교체.
  - API 주소를 바꾸면 키를 다시 입력해야 저장된다 [완료].
- 방문자 화면에는 운영자 입구·모델명·비용이 없다 [완료, test_app]. 바탕화면 바로가기는 만들지 않고, 프로그램 폴더 안에 '운영자 설정.url'만 둔다(P2).
